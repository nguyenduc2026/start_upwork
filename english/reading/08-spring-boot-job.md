## 2. Bài đọc

<!-- passage:start -->
We need a Spring Boot developer for a small taskboard API. The frontend is already available, but several backend endpoints are missing. The first task is to add filters for task status and owner.

The project uses Java and a relational database. You should be comfortable reading existing code and writing tests. We do not need a full rewrite. The new API should follow the current response format so the React app can use it without major changes.

This is a fixed-price task with a clear review checklist. Please include the source code, tests, and a short setup guide in the delivery. If the tests fail, we will ask for a revision before approval. We expect the first version within five working days after you receive access.

Our team is available for questions until 5 PM GMT+7. We hold calls on Tuesdays. To apply, share one relevant backend project and explain how you test filters. Could you also tell us which assumptions you need to confirm before giving an estimate?
<!-- passage:end -->

## 4. Đọc hiểu

### A. Đúng (T) hay Sai (F)?

Dựa vào bài đọc, đánh T/F. Với câu sai, chỉ ra thông tin đúng thay thế.

1. The client wants a complete rewrite.
2. The first task adds status and owner filters.
3. Tests are excluded from delivery.
4. The team holds calls on Tuesdays.
5. The five working days begin before access is received.

<details>
<summary>Đáp án 4A</summary>

1. **F** — đối chiếu: *We do not need a full rewrite.*
2. **T** — đối chiếu: *The first task is to add filters for task status and owner.*
3. **F** — đối chiếu: *Please include the source code, tests, and a short setup guide in the delivery.*
4. **T** — đối chiếu: *We hold calls on Tuesdays.*
5. **F** — đối chiếu: *We expect the first version within five working days after you receive access.*

</details>

## 5. Từ vựng trong bài

IPA tham khảo theo Anh–Anh; audio mẫu dùng giọng Mỹ nên một số nguyên âm và âm r có thể khác. n = danh từ, v = động từ, adj = tính từ. Dấu ˈ đứng trước âm tiết nhấn chính. Mỗi ví dụ dưới đây là câu trích từ đoạn đọc, có thể chứa dạng chia của từ.

| Từ | Phiên âm | Loại | Nghĩa | Câu trong bài |
|---|---|---|---|---|
| endpoint | /ˈendpɔɪnt/ | n | 1 đường dẫn API | The frontend is already available, but several backend endpoints are missing. |
| filter | /ˈfɪltə/ | n/v | bộ lọc; lọc theo điều kiện | The first task is to add filters for task status and owner. |
| owner | /ˈəʊnə/ | n | người chịu trách nhiệm chính | The first task is to add filters for task status and owner. |
| database | /ˈdeɪtəbeɪs/ | n | cơ sở dữ liệu | The project uses Java and a relational database. |
| rewrite | /ˈriːraɪt/ | n | việc viết lại toàn bộ | We do not need a full rewrite. |
| format | /ˈfɔːmæt/ | n | định dạng, cấu trúc dữ liệu | The new API should follow the current response format so the React app can use it without major changes. |
| checklist | /ˈtʃeklɪst/ | n | danh sách các mục cần kiểm tra | This is a fixed-price task with a clear review checklist. |
| delivery | /dɪˈlɪvəri/ | n | việc gửi, chuyển hoặc bàn giao | Please include the source code, tests, and a short setup guide in the delivery. |
| revision | /rɪˈvɪʒən/ | n | lần hoặc bản chỉnh sửa | If the tests fail, we will ask for a revision before approval. |

**Anki:** lưu khối dưới ở dạng UTF-8, nhập với dấu phân cách **Semicolon** (dấu chấm phẩy), hai trường mặt trước / mặt sau. Mỗi dòng gồm nghĩa và câu trong bài.

## 6. Ngữ pháp trong bài

### A. Tìm và phân loại

Dùng các bài grammar được liên kết ở đầu bài nếu cần nhắc lại công thức. Giải thích ngắn bằng tiếng Việt vì sao cấu trúc phù hợp với ý trong câu.

1. Tìm và chép câu dùng **điều kiện loại 1**. Nội dung/chức năng cần tìm: nêu điều kiện yêu cầu sửa. In đậm từ hoặc cấu trúc thể hiện cách dùng đó.
2. Tìm và chép câu dùng **until + mốc**. Nội dung/chức năng cần tìm: nêu thời điểm kết thúc hỗ trợ. In đậm từ hoặc cấu trúc thể hiện cách dùng đó.
3. Tìm và chép câu dùng **on + ngày**. Nội dung/chức năng cần tìm: nói lịch gọi hằng tuần. In đậm từ hoặc cấu trúc thể hiện cách dùng đó.
4. Tìm và chép câu dùng **should + V**. Nội dung/chức năng cần tìm: ôn cách nêu yêu cầu mong đợi. In đậm từ hoặc cấu trúc thể hiện cách dùng đó.

<details>
<summary>Đáp án gợi ý 6A</summary>

1. *If the tests fail, we will ask for a revision before approval.* → **điều kiện loại 1**: nêu điều kiện yêu cầu sửa.
2. *Our team is available for questions until 5 PM GMT+7.* → **until + mốc**: nêu thời điểm kết thúc hỗ trợ.
3. *We hold calls on Tuesdays.* → **on + ngày**: nói lịch gọi hằng tuần.
4. *You should be comfortable reading existing code and writing tests.* → **should + V**: ôn cách nêu yêu cầu mong đợi.

</details>

### B. Ôn bài trước

Ôn [Milestone & thanh toán trên Upwork](07-milestones-payments.md). Điền hai từ/cụm, mỗi từ dùng một lần, chia dạng theo câu: **fixed-price, support**.

1. A ___ project can have several milestones.
2. If a status is unclear, she can ask ___.

<details>
<summary>Đáp án ôn bài trước</summary>

1. fixed-price — có giá cố định. Câu gốc: *A fixed-price project can have several milestones.*
2. support — bộ phận hỗ trợ. Câu gốc: *If a status is unclear, she can ask support.*

</details>

## 7. Tóm tắt và phản hồi

**A.** Viết 3–5 câu tiếng Anh tóm tắt thông tin chính. Giữ đúng mức chắc chắn của bài; không biến dự kiến thành kết quả đã xác nhận.

**B.** Viết 1–2 câu tiếng Anh nêu phản hồi hoặc điều bạn muốn hỏi tiếp, có liên quan đến tình huống.

<details>
<summary>Gợi ý mục 7 — xem sau khi tự viết</summary>

**A. Tóm tắt mẫu:** The client needs missing Spring Boot endpoints for task filters. The work should preserve the existing response format and include tests and a setup guide. Delivery is expected within five working days after access is received.

**B. Phản hồi mẫu:** I would ask for examples of the existing responses. I would confirm filter behavior before estimating.

Phần phản hồi là một cách viết tham khảo, không phải thông tin mới của văn bản.

</details>
