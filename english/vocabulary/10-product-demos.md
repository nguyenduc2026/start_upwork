# Từ vựng 10 — Trình bày & demo sản phẩm

> **Tuần 10** · Giai đoạn 3 · 6 ngày × 10 phút + 20 phút luyện cuối tuần
> **Lịch học:** Ngày 1–2: nhóm 1–2 · Ngày 3–4: nhóm 3–4 · Ngày 5: họ từ và cụm từ · Ngày 6: phân biệt từ, phát âm, mẫu câu · Cuối tuần: bài tập. Ôn Anki trong thời gian mỗi ngày.
> **Bài trước:** [Cuộc gọi & họp](09-calls-meetings.md). IPA Anh–Anh; n = danh từ, v = động từ, adj = tính từ.

**Sau bài này bạn có thể:** giới thiệu một luồng chức năng theo thứ tự, mô tả đầu vào/kết quả và nói rõ lợi ích, giới hạn của bản demo.

**Khi nào dùng:** gửi bản demo taskboard hoặc hệ thống đặt vé, viết lời giới thiệu ngắn trước khi trình bày và ghi chú điều client cần kiểm tra. Với từ vựng khó hơn B1, học theo cụm mẫu ngắn thay vì cố dùng câu dài.

## 1. Từ vựng

## 2. Họ từ (Word Family)

| Họ từ | Ví dụ và lưu ý |
|---|---|
| demonstrate → demonstration (n) → demo (viết ngắn) | The demonstration covers checkout. |
| navigate → navigation | Users can navigate between projects. |
| select → selection (n) → selected | The selected seat is highlighted. |
| submit → submission (n) → submitted | The form was submitted successfully. |
| validate → validation → valid / invalid | Invalid input shows an error message. |
| improve → improvement | We improved the mobile layout. |

*Functionality* thường không đếm được khi nói tổng thể: *core functionality*. Khi đếm các tính năng cụ thể, dùng *features*: *three new features*. *Benefit* trả lời “người dùng được lợi gì”; không chỉ lặp tên công nghệ.

## 3. Cụm từ đi kèm (Collocations)

| Cụm | Nghĩa | Ví dụ |
|---|---|---|
| give an overview | giới thiệu tổng quan | I'll give an overview before the walkthrough. |
| walk someone through something | hướng dẫn ai từng bước | I'll walk you through the checkout flow. |
| demonstrate a feature | trình diễn tính năng | I'll demonstrate the task filter. |
| select an option | chọn phương án/mục | Select an option from the menu. |
| submit a form | gửi biểu mẫu | Submit the form after entering your details. |
| validate user input | kiểm tra dữ liệu người dùng | The API validates user input. |
| highlight a benefit | nêu lợi ích đáng chú ý | I'd like to highlight a benefit for support staff. |
| explain a limitation | giải thích giới hạn | I'll explain the current limitation before testing. |

## 4. Từ dễ nhầm

| Cặp/nhóm | Phân biệt | Ví dụ |
|---|---|---|
| overview / walkthrough | Tổng quan ngắn ↔ đi qua từng bước; có thể kết hợp trong một buổi | Start with an overview, then give a walkthrough. |
| feature / benefit | Sản phẩm làm được gì ↔ điều đó giúp người dùng như thế nào | Feature: task filters. Benefit: users find urgent work faster. |
| input / output | Dữ liệu đưa vào ↔ kết quả tạo ra | Input: an email address. Output: a confirmation message. |
| validation / authentication | Kiểm tra dữ liệu theo quy tắc ↔ xác thực danh tính | Validation checks the email format. Authentication checks who is signing in. |

*Demo* có thể dùng dữ liệu test hoặc mô phỏng. Nếu thanh toán đang dùng test mode, nói rõ *This demo uses test payments*. Không nói đã xử lý giao dịch thật hoặc đã chạy production nếu chưa đúng.

## 5. Lỗi phát âm thường gặp

| Từ | IPA | Lỗi cần tránh |
|---|---|---|
| walkthrough | /ˈwɔːkθruː/ | L không đọc; giữ /k/ và /θ/ |
| demonstrate | /ˈdemənstreɪt/ | Nhấn âm đầu, không nhấn -strate |
| functionality | /ˌfʌŋkʃəˈnæləti/ | Nhấn chính -nal-, không nhấn func- |
| submit | /səbˈmɪt/ | Nhấn âm thứ hai; giữ /t/ |
| validation | /ˌvælɪˈdeɪʃən/ | Nhấn chính -da-, không nhấn âm đầu |

Đối chiếu *walkthrough*: [Cambridge Dictionary](https://dictionary.cambridge.org/pronunciation/english/walkthrough).

## 6. Mẫu câu thực tế

> Hi Anna, I've prepared a **demo** of the booking app. It includes an **overview** and a short **walkthrough** of checkout. Users can **select** a seat and **submit** the booking form. The API checks **input** through **validation**. The main **benefit** is a clearer booking flow. One current **limitation** is that payments use test mode. Could you review the failed-payment **scenario** as well?

Mẫu cho biết sẽ xem gì, lợi ích gì và giới hạn nào. Đây là tin nhắn giới thiệu demo; bài speaking sẽ phát triển thành lời trình bày để luyện nói.

## 8. Bài tập

### A. Điền từ

Dùng mỗi từ một lần: **overview, walkthrough, dashboard, select, submit, input, benefit, limitation**.

1. Start with a quick ___ of the whole app.
2. Then give a step-by-step ___ of checkout.
3. The ___ shows the number of open tasks.
4. First, ___ an available seat.
5. Then ___ the booking form.
6. The API checks the user's ___ before saving it.
7. Easier task tracking is the main ___ for users.
8. Test-only payments are a current ___ of this demo.

<details>
<summary>Đáp án A</summary>

1. overview · 2. walkthrough · 3. dashboard · 4. select · 5. submit · 6. input · 7. benefit · 8. limitation.

</details>

### B. Chọn từ đúng

1. Đi từng bước: I'll give a (walkthrough / overview).
2. Bộ lọc task là tính năng: Filtering is a (feature / benefit).
3. Dữ liệu người dùng gửi vào: The form checks the (input / output).
4. Kiểm tra định dạng email: This is (validation / authentication).
5. Người dùng tìm task nhanh hơn là (a benefit / an input).

<details>
<summary>Đáp án B</summary>

1. walkthrough · 2. feature · 3. input · 4. validation · 5. a benefit.

</details>

### C. Dịch sang tiếng Anh

1. Tôi sẽ hướng dẫn bạn từng bước qua luồng checkout.
2. Bạn có thể lọc task theo trạng thái.
3. Một giới hạn hiện tại là thanh toán dùng chế độ test.
4. Bạn có thể chia sẻ nội dung cuộc họp trước cuộc gọi không? (ôn Bài 09)
5. Tôi sẽ gửi các đầu việc cần làm sau cuộc họp. (ôn Bài 09)

<details>
<summary>Đáp án gợi ý C</summary>

1. I'll walk you through the checkout flow.
2. You can filter tasks by status.
3. One current limitation is that payments use test mode.
4. Could you share the agenda before the call?
5. I'll send the action items after the meeting.

</details>

### D. Viết tin nhắn giới thiệu demo

Chọn project đặt vé hoặc taskboard. Viết 6–8 câu gồm tổng quan, hai thao tác người dùng, một kết quả, một lợi ích, một giới hạn và lời mời phản hồi. Dùng ít nhất 5 từ mục 1, in đậm từ đã dùng. Có thể dùng giả định cho bài tập nhưng phải nói rõ đây là demo/test nếu mô tả tính năng chưa có thật.

<details>
<summary>Gợi ý D — xem sau khi tự viết</summary>

I've prepared a test **demo** of the booking app. It starts with an **overview** of the **interface**. The **walkthrough** shows how to **select** a seat and **submit** the booking form. The **output** is a booking confirmation. The main **benefit** is a clearer booking flow. One **limitation** is that payments use test mode. Could you share your feedback on this **scenario**?

</details>
